Kimi K3: Open Frontier Intelligence

A 2.8-trillion-parameter Mixture-of-Experts model with native vision and a one-million-token context window — read here with the machinery unpacked.

00Abstract

Kimi K3 is built on two architectural ideas that carry most of the paper: Kimi Delta Attention, which changes how information moves along the sequence, and Attention Residuals, which changes how it moves through depth. Together with Stable LatentMoE — 16 of 896 routed experts firing per token — and refined data recipes, the team reports roughly a 2.5× improvement in scaling efficiency over Kimi K2.

Post-training is reinforcement learning across general, agentic and coding domains at several reasoning-effort levels, consolidated into one model by multi-teacher on-policy distillation. On the benchmark suite, K3 trails Claude Fable 5 and GPT-5.6 Sol overall while beating every other model tested, open or proprietary.

01Introduction: two axes

The framing of the paper is that scaling now has two axes. The first is the old one: more compute before deployment, bigger models on more data — scaling laws. The second is test-time compute: reasoning models that spend tokens thinking, call tools in a loop, or coordinate parallel agents.

The open-source ecosystem, they argue, has moved fast on the second axis and slowly on the first — most open models sit at or just above 1T parameters. Applying ever-more-sophisticated RL to pre-trained foundations of the same size risks convergence while the gap to the strongest closed systems widens. K3's answer is to push both at once: a 3T-class pre-trained base, plus RL, reasoning effort, and long-horizon interaction at 1M context.

The bet. Architecture buys the base; RL buys the behaviour; infrastructure is what makes both physically possible at 2.8T parameters and million-token trajectories. The paper is organised in exactly that order.

02Model architecture

The design scales information flow along three dimensions: sequence length, network depth, and model width.

  • Sequence — hybrid attention: three KDA layers then one Gated MLA layer, repeated.
  • Depth — Attention Residuals: each layer attends over the outputs of preceding layers instead of accumulating them.
  • Width — Stable LatentMoE: sparse channel mixing, 16 of 896 routed experts per token.

Vision is native: MoonViT-V2 encodes images and video and a light projector maps them into the same embedding space, with no post-hoc alignment stage. Optimisation uses Per-Head Muon.

2.1 Hybrid attention

Each block is 3 KDA layers followed by 1 Gated MLA layer — a 3:1 mixing ratio — and one extra Gated MLA layer sits at the end of the backbone so the final layer always performs global attention. The intuition: linear layers do cheap recency-aware mixing, and the periodic global layers preserve exact long-range lookup.

2.1.1 Kimi Delta Attention

KDA extends the delta rule with a channel-wise forget gate. For a single head with query and key qt, kt, value vt and recurrent state St:

S_t = (I − β_t k_t k_tᵀ) · Diag(α_t) · S_{t−1} + β_t k_t v_tᵀ o_t = S_tᵀ q_t The state is a matrix, not a growing cache. Diag(α) decays it channel by channel; the (I − βkkᵀ) factor erases the part of the state that the current key would have retrieved, before writing the new value in its place.

Training and prefill use a chunkwise parallel form: recurrent across chunks, parallel within each. The one numerical wrinkle is that the chunk form divides keys by a cumulative decay product, which can overflow — solved by lower-bounded decay, a change that also removes an awkward kernel path and lets every tile go through the Tensor Cores. Finally the output gate is promoted from low-rank to a full-rank input-dependent projection, an instance of data-dependent gating.

2.1.2 Gated MLA

Multi-head Latent Attention compresses each token's key–value pair into one low-dimensional latent vector, so the KV cache shrinks while global attention is retained. K3 applies No Position Encoding to all MLA layers: the KDA layers supply position sensitivity through their decay, so there is no RoPE base to retune when the context is extended to 1M. Attention output is kept in FP32 during training to correct a biased rounding error in flash attention.

2.2 Attention Residuals

A standard residual stream compresses everything a network has computed into one running state — a bottleneck reminiscent of an RNN over time. AttnRes applies the attention trick to depth: each layer holds a learnable pseudo-query and attends over the outputs of all preceding layers, retrieving rather than accumulating.

Doing that literally costs O(Ld) memory for keeping every layer output alive, so K3 uses Block AttnRes: layers are grouped into 8 blocks of 12, each block summed into a single representation, and cross-block attention runs over those N summaries. Memory and cross-stage communication drop to O(Nd), and inference-time state is bounded, with results merged by online softmax.

2.3 Stable LatentMoE

In an ordinary MoE every selected expert receives the full-width token vector, so traffic grows with the number of active experts. LatentMoE splits the widths: shared experts keep a full-width path, routed experts work in a compact latent space. That makes 896 routed experts with 16 active affordable — a sparsity of 56.

Extreme sparsity breaks two things. First, the routed path becomes a chain of nearly four consecutive matmuls and blows up internal activations; fixes are an RMSNorm before the up-projection and a new activation, SiTU-GLU, which smoothly caps both branches of SwiGLU. Second, load balancing nearly 10³ experts exceeds what sign-step bias updates handle well; the fix is Quantile Balancing, computed in practice from a per-expert histogram.

2.4–2.5 Native vision and Per-Head Muon

The vision encoder is trained from scratch with next-token prediction rather than initialised from a contrastively pre-trained model like SigLIP — chosen for training stability, since the SigLIP-initialised tower showed persistent gradient-norm spikes. A 2×2 pixel shuffle cuts visual tokens fourfold before projection.

Muon is the optimiser for matrix parameters; K3 refines it per attention head, orthogonalising each head's momentum block separately so that large-gradient heads stop dominating the shared update direction — Per-Head Muon.

03Pre-training

Four text domains (web, code, mathematics, knowledge) plus a large vision corpus, filtered by heuristics, classifier quality scoring and deduplication, with sampling rates set by ablations on small models. Knowledge and maths corpora are rephrased with diverse prompting and verified against the source. Vision data adds programmatic pairs — code next to its rendered output — across SVG, 3D assets, webpages, games and CAD.

Dedicated scaling-law studies retune batch size, learning rate, tokens-per-parameter and model shape, and they consistently favour cosine decay over WSD once each schedule is given its own optimal hyperparameters.

Context grows on a four-stage curriculum: 8K → 64K during pre-training, then 256K → 1M during cooldown, keeping the expensive long-sequence work inside a small slice of the budget. Long natural documents are scarce and often junk, so they are cleaned, upsampled, and supplemented with synthetic long-context tasks built by permuting and concatenating documents so answers can only be found by attending across the whole window.

04Post-training

Three stages: supervised fine-tuning for a cold-start policy, RL to build domain experts at each reasoning effort, and multi-teacher on-policy distillation to fold nine experts (3 domains × 3 efforts) back into one model.

RL spans general tasks, general agents and coding agents. The rollout scheme is partial rollouts: generation pauses once a fraction of trajectories finish, and unfinished ones resume next iteration from a preserved sandbox state — which makes training data go stale, tolerated by a per-token regularizer.

Reasoning effort is trained by budget control: each problem gets an initial token budget, and trajectories that exceed a scaled threshold are given reward −1. For non-verifiable tasks the judge is an agentic generative reward model with a mandatory rubric protocol and a verbosity cap to blunt reward hacking.

Deployment shapes training too: quantization-aware training in MXFP4 weights and MXFP8 activations runs through SFT and RL so rollout and training share one numerical scheme, and the pre-trained multi-token-prediction layer is fine-tuned into an EAGLE-3 draft model for speculative decoding, optimising the acceptance rate directly.

4.2 Environments

The environments are as much of the contribution as the algorithm.

  • A white-box harness. Tool interfaces, prompts, context management, skills, memories and subagents are composable modules, so the same model trains across configurations that imitate Kimi Code, Claude Code, Codex and others rather than overfitting one.
  • Knowledge-graph task synthesis. Agents grow a self-evolving concept DAG, sample nodes for granularity and coverage, retrieve real materials, and synthesise tasks from them.
  • Kernel optimisation. Reward 0.5 for matching an expert implementation, rising toward 1 near the hardware roofline, with a detector penalising CUDA graph replay, input caching and precision cheats.
  • Personal assistant tasks. Mock Gmail, Notion, Slack and Canvas; persistent multi-day worlds; up to thousands of tool calls and millions of tokens per rollout.
  • Autonomous execution. Goal, budget, and an independent verifier — no reference trajectory. Reward is graded on the final environment state, not the agent's own claim of success.

05Infrastructure

Three unusual pressures at once: a hybrid recurrent/global attention stack, 3T-class sparse multimodal training, and million-token agentic rollouts.

5.1 KDA kernels and context parallelism

The chunkwise form alternates parallel and serial phases, leaving SMs idle during propagation, so FlashKDA overlaps intra-chunk computation with cross-chunk state propagation. Across devices, plain summation of local states does not work for KDA — the delta rule applies a token-dependent matrix to the incoming state — so KDA Context Parallelism decomposes each segment into a cumulative transition plus a locally generated state, which compose associatively and can therefore be resolved by a prefix scan over a fixed-size all-gather.

5.2 3T-class pre-training

Training combines pipeline parallelism with virtual stages, expert parallelism, ZeRO-1 data parallelism, pipeline ZeRO-2 gradient sharding and context parallelism. The MoE-specific contribution is MoonEP: perfect load balance via dynamic redundant experts, with a proof that at most E/R redundant experts per rank always suffice, which turns token counts into static shapes and removes per-layer host synchronisation.

Memory is handled by a unified activation manager where recomputation, FP8 quantization and offload are pluggable per-tensor policies; gradients are sharded and parked in CPU memory; Muon's orthogonalisation gathers only the shards a rank owns, over P2P, instead of an all-gather of the whole parameter buffer.

5.3–5.4 Agentic RL and serving

Long-context RL contends for memory between rollout KV cache and training. K3 writes idle prefixes back to an external CPU DRAM pool, offloads training state to NVMe between iterations, and throttles rollout concurrency from live signals. Sandboxes are Firecracker microVMs with pause/fork/snapshot; over 51 million sandboxes were created during the project.

Serving has to reuse work across requests, which for a hybrid model means the KDA recurrent state and the MLA cache must be restorable at the same boundary. The fix decouples granularities: prefix hashing on 512-token hash blocks, with sparse KDA checkpoints saved only at hash-aligned positions. Cache pages store each head's state contiguously so that prefill and decode nodes can run at different tensor-parallel degrees. Above a single instance, sessions are pinned by consistent hashing to a primary and secondary cluster, and request classes get separate budgets so a burst of million-token jobs cannot wreck time-to-first-token for short ones.

06Evaluation

Four axes — reasoning & knowledge, coding, agentic, vision — against Claude Fable 5, GPT-5.6 Sol, Claude Opus 4.8, GPT-5.5 and GLM-5.2. All at maximum reasoning effort. Read the numbers with the usual caveats: harnesses differ, some scores are cited from third parties on given dates, and Fable 5 results include fallback behaviour.

  • Reasoning. 93.5 on GPQA Diamond, competitive; but 43.5/56.0 on HLE-Full and 23.4 on CritPt, behind the leaders — research-level reasoning is named as the weak spot.
  • Coding. Best on ProgramBench (77.8) and SWE-Marathon (42.0, 7 points ahead of Fable 5); second on FrontierSWE (81.2 vs 86.6).
  • Agentic. Leads BrowseComp (91.2), DeepSearchQA, MCPMark-Verified, τ³-Banking, Harvey Lab-AA; trails on the Elo-rated knowledge-work suites.
  • Vision. Highest on OmniDocBench (91.1); ties Fable 5 on ZeroBench-main at 23.0 pass@5, rising to 41.0 with a Python tool.

The in-house suite is more revealing than the public one: clear leads on orchestration and deep research, a coding-experience score above its raw task score, and clear deficits on agent behaviour and multi-role enterprise collaboration.

Section 6.2.2 is a cyber-capability evaluation — vulnerability discovery and end-to-end exploit development — reported openly, including the note that Anthropic and OpenAI models refuse these tasks so no comparison was possible. On cost efficiency, K3 sits on or near the frontier of score-per-dollar on all four measured suites.

07Case studies

Four claims worth singling out: a 24-hour GPU kernel optimisation run cutting AttnRes latency from 283.6 ms to 114.4 ms; a from-scratch Triton-like compiler with PTX codegen whose matmul reaches ~90% of measured machine roof; a 48-hour autonomous run producing a verified inference-chip RTL prototype; and an astrophysics reproduction — 300+ equations of state, 3,000 lines of Python — in about two hours.

What to take from it. Almost every architectural choice here is paid for by a systems change, and vice versa: bounded decay exists to reach the Tensor Cores, LatentMoE exists to make wide routing affordable, Block AttnRes exists to bound the inference state, MoonEP exists so shapes can be static. The paper is a good demonstration that at this scale, model design is systems design.
